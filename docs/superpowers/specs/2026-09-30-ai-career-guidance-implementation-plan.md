## 2. 第一周：确认接口并跑通最小闭环

### 目标

本地可以打开页面，填写画像、选择岗位、提交问题并看到返回结果。第一周允许先返回固定示例答案，不等待 RAG 完成。

### 任务

| ID | 任务 | 负责人 | 完成条件 |
|---|---|---|---|
| W1-1 | 建立代码目录、依赖清单、`.gitignore` 和 `.env.example` | 马晨鑫 | 新环境按说明安装依赖；真实密钥不会被提交 |
| W1-2 | 定义画像、岗位、对话、来源和计划的 JSON 字段 | 马晨鑫、许莉苹、张润泽 | 前后端字段名称和类型有书面约定 |
| W1-3 | 创建 FastAPI 应用和 `/health`、`/jobs` 接口 | 马晨鑫 | 服务启动后健康检查返回成功，能返回三个岗位 |
| W1-4 | 创建 Streamlit 页面导航和四个页面骨架 | 许莉苹 | 画像、岗位探索、职业分析、行动计划页面均可打开 |
| W1-5 | 建立 SQLite 初始化和画像新增/读取/修改 | 张润泽 | 保存画像后重启服务仍可读取 |
| W1-6 | 编写三个岗位的初始能力条目和岗位卡片内容 | 王晨鑫 | 后端、前端、测试开发各有工作、技能、匹配和差距字段 |
| W1-7 | 编写岗位资料 Markdown 模板并提交第一批示例资料 | 许国洋、王赛博 | 示例资料格式统一，来源状态标明为 placeholder |
| W1-8 | 准备首轮固定演示用户画像和五条演示问题 | 宋子轩、赵宸兴 | 有可重复使用的演示输入，不含真实个人隐私 |
| W1-9 | 记录环境启动步骤 | 张岩、赵宸兴 | 另一位组员可以按步骤启动前后端 |

### 周验收

完成“画像填写并保存 → 查看三岗位 → 选择岗位 → 提交一个问题 → 页面显示固定示例答案”。

## 3. 第二周：接入模型、知识检索和来源展示

### 目标

用户提问时，系统可以检索就业资料、调用模型，并显示真实或占位来源状态。

### 任务

| ID | 任务 | 负责人 | 完成条件 |
|---|---|---|---|
| W2-1 | 实现本地模型配置读取和 API 连通性检查 | 马晨鑫、赵宸兴 | 模型名、Base URL 和密钥通过环境变量读取；失败有明确错误 |
| W2-2 | 固定模型输入/输出格式和提示词 | 马晨鑫、王晨鑫 | 分析字段稳定为优势、差距、行动、来源和不确定项 |
| W2-3 | 编写知识文档加载、清洗和切分脚本 | 许国洋 | 可处理约定格式的 Markdown 文档并报告无效元数据 |
| W2-4 | 完成 Embedding 和 Chroma 本地持久化 | 许国洋 | 入库后重启程序，向量资料仍可检索 |
| W2-5 | 实现按问题和岗位筛选的基础向量检索 | 许国洋、马晨鑫 | 三岗位问题优先取回对应岗位资料片段 |
| W2-6 | 将检索内容及来源传给模型并返回前端 | 马晨鑫、许莉苹 | 页面能展示答案、来源标题、更新时间和 placeholder 状态 |
| W2-7 | 加入无依据和模型服务失败状态 | 马晨鑫、许莉苹 | 空检索、超时、错误密钥都显示可理解的提示 |
| W2-8 | 整理首批岗位、招聘流程和学习资料 | 王赛博、王晨鑫、赵宸兴 | 有一批格式统一、注明来源或 placeholder 的资料 |
| W2-9 | 建立 10 个固定问答及期望资料类别 | 宋子轩 | 每个问题有岗位、期望主题和判定记录字段 |
| W2-10 | 完成三个岗位卡片与画像匹配文字 | 许莉苹、王晨鑫 | 卡片显示工作、技能、匹配点、差距，不显示匹配百分比 |

### 周验收

至少对 10 个固定问题检查检索结果；回答显示来源状态；资料不足时不伪造来源；三个岗位都能查看和选择。

## 4. 第三周：完成分析、体验反馈和四周计划

### 目标

完成岗位选择后的主要价值：有依据的职业分析、可选体验任务和可保存的个性化计划。

### 任务

| ID | 任务 | 负责人 | 完成条件 |
|---|---|---|---|
| W3-1 | 建立会话和消息表及读写方法 | 张润泽 | 重启后可恢复会话消息和来源元数据 |
| W3-2 | 建立分析结果保存和版本规则 | 张润泽、马晨鑫 | 切换岗位重新分析后不会误显示旧结果 |
| W3-3 | 完成职业分析页面四个区块 | 许莉苹、马晨鑫 | 优势、差距、建议行动、来源分别清楚展示 |
| W3-4 | 实现三个可选体验任务说明页 | 许莉苹、王晨鑫 | 用户可进入任务或选择跳过，两条路径都能继续 |
| W3-5 | 保存体验任务参与和反馈 | 张润泽 | 记录参与/跳过、兴趣、难度、继续意愿；跳过不强制填写 |
| W3-6 | 根据每周可投入时间生成四周计划 | 马晨鑫、王晨鑫 | 每周含目标、任务、用时、完成标准，任务对应已识别差距 |
| W3-7 | 保存并读取行动计划 | 张润泽 | 生成计划后可从数据库重新加载 |

| W3-9 | 检查计划用时和内容具体性 | 宋子轩 | 计划预算合理；完成标准可观察；空泛项记录为缺陷 |

### 周验收

完成“画像 → 岗位比较 → 参加或跳过体验 → 选择岗位 → 职业分析和对话 → 四周计划 → 保存和导出”。

## 5. 第四周：稳定性、演示和路演冻结

### 目标

现场按固定脚本稳定演示。第四周优先修复和排练，不再加入高风险新功能。

### 任务

| ID | 任务 | 负责人 | 完成条件 |
|---|---|---|---|
| W4-1 | 对全部核心流程做一次端到端回归 | 宋子轩、全体开发 | 验收场景 A-F 均有通过/失败记录 |
| W4-2 | 修复阻断演示的问题 | 对应模块负责人 | 高优先级 Bug 清零，其他问题有绕行方案 |
| W4-3 | 建立一份可复位的演示数据库和知识库 | 张润泽、许国洋 | 可通过说明一键或按步骤恢复固定数据 |
| W4-4 | 验证模型 API 不可用时的备用演示方式 | 赵宸兴、马晨鑫 | 可用预存结果完成流程说明，不伪装为实时调用 |
| W4-5 | 完成路演 PPT、架构图和流程图 | 张岩 | 内容只描述已实现或明确标注的功能 |
| W4-6 | 编写并计时演示脚本 | 张岩、许莉苹 | 5 分钟左右完整走通主线 |
| W4-7 | 执行两次全流程彩排 | 全体 | 至少一次由非主要开发者按说明完成操作 |
| W4-8 | 冻结路演版本并备份 | 马晨鑫 | 保存可运行代码版本、配置说明和演示数据副本 |

### 周验收

由未负责主流程开发的组员按脚本从启动开始演示，能够展示岗位比较、可选体验、来源、分析、计划和导出。

## 6. 路演验收清单

- [ ] 前端和后端按运行说明启动成功。
- [ ] API 密钥不出现在仓库、日志或截图中。
- [ ] 固定用户画像能保存和重新读取。
- [ ] 三个岗位卡片都显示工作内容、技能、匹配点和差距。
- [ ] 体验任务可以开始，也可以跳过。
- [ ] 跳过体验后仍可选岗并完成分析。
- [ ] 职业分析不显示无依据的匹配百分比。
- [ ] 回答显示来源标题、链接/空链接状态、更新时间和资料类型。
- [ ] placeholder 清晰标为示例，不使用虚假公司或链接。
- [ ] 无相关资料时显示无可靠依据的提示。
- [ ] 四周计划按用户时间预算生成且每项有完成标准。
- [ ] 画像、会话、分析和计划可持久保存。
- [ ] Markdown 导出内容完整、可读。
- [ ] API 失败时有备用流程和可理解的错误提示。
- [ ] 路演脚本与实际版本一致。

## 7. 协作约定

1. 每个任务只指定一位直接负责人，其他成员可以协助。
2. 每周至少一次集成演示，持续保持主分支可运行。
3. 接口字段变更要同步前后端和数据库负责人，并更新接口说明。
4. 内容成员提交经过整理的资料和来源，不只提交链接。
5. 测试成员以可复现步骤报告问题，并记录修复后的结果。
6. 新想法先排入第二优先级；除非核心演示受益明确，不挤占已承诺功能。
7. 模型调用、混合检索和重排序都以可观察的产品效果为采用依据。

## 8. 需要团队一起确认的参数

实现前由小组补齐以下配置，不需要公开 API 密钥：

- 模型服务支持的模型名称；
- 中转服务的 API 协议是否兼容 OpenAI Chat Completions；
- Embedding 使用云端模型还是本地模型；
- 本地开发电脑的 Python 版本；
- 示例知识资料首批条目和后续替换负责人；
- 体验任务是让用户提交简短文本，还是只收集体验反馈。
