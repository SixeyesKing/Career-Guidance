# AI 职业规划助手 A1 全站 UI 改版设计

## 1. 目标与边界

本次改版以 A1 专业工作台草稿为视觉基准，统一 Streamlit 前端的首页、个人画像、岗位探索、职业分析、行动计划和侧边栏。目标是提升信息层级、可读性、导航一致性和答辩展示效果。

本次只调整前端展示层、布局、CSS 和必要的连接配置检查，不改变业务逻辑、数据库结构、API 数据格式、模型调用流程、检索算法和计划生成规则。

## 2. 视觉系统

- 主色：深绿色，用于主按钮、当前导航、主要状态和关键操作。
- 辅色：橙色，用于提醒、待确认信息和行动重点。
- 页面背景：浅灰白色。
- 内容区域：白色背景、细边框、轻微圆角，避免多层嵌套卡片。
- 字体层级：页面标题、说明文字、状态标签、正文和辅助信息明确区分。
- 页面步骤标识：使用少量 `01 / PROFILE`、`02 / EXPLORE`、`03 / ANALYSIS`、`04 / PLAN`。
- 响应式布局：窄屏时减少列数，保证文字和操作不发生重叠。

## 3. 页面设计

### 3.1 今日概览

- 使用工作台式左侧导航。
- 顶部显示用户年级、专业等已保存画像摘要。
- 主区域突出建议的下一步。
- 展示每周职业探索与求职准备时间。
- 展示最近保存的分析、对话和计划。
- 展示后端开发、前端开发、测试开发三个岗位方向。
- 首次使用时根据实际画像状态展示填写画像引导。

### 3.2 个人画像

保留现有字段和保存逻辑，按基本信息、技能与经历、兴趣与目标、时间预算进行视觉分区。保存按钮、成功状态和未填写信息说明需要清晰可见。

### 3.3 岗位探索

- 三个岗位使用统一的并排比较卡片。
- 卡片展示岗位简介、常见工作和能力要求。
- 当前岗位使用绿色边框和状态标签强调。
- 体验任务作为可选区域，保留开始和跳过行为。
- 资料状态、来源和更新时间单独展示。
- 页面底部保留继续进行职业分析的操作。

### 3.4 职业分析

- 顶部展示目标岗位和更新分析操作。
- 分栏展示已提到的基础与待确认信息。
- 待确认信息使用橙色标记，并明确表达“未知不等于不足”。
- 建议行动独立成区，保留完成标准。
- 继续咨询区域与分析结果区分展示。
- 资料来源和资料状态持续可见。

### 3.5 行动计划

- 顶部展示目标岗位和 Markdown 下载操作。
- 独立展示每周可投入时间和计划预算说明。
- 每周内容采用清晰的信息行，展示目标、任务、完成标准和预计时长。
- 保留周预算进度、历史计划切换、重新生成、警告、资源链接和下载行为。
- 演示模式和资料状态使用统一提醒样式。

## 4. 侧边栏设计

侧边栏包含品牌区、工作空间导航和运行状态区。导航项目包括今日概览、个人画像、岗位探索、职业分析和行动计划。状态区显示后端连接、模型连接、聊天模型名称以及向量检索或词项检索状态。页面切换机制保持现有 `st.sidebar.radio` 逻辑。

## 5. 后端检查范围

改版过程中检查以下接口和连接行为：

- `/health`、`/status`
- `/profile`、`/jobs`
- `/chat`
- `/analysis/{job_category}`
- `/plans`、`/plans/{job_category}`
- `/knowledge/status`

重点确认前端 API 地址读取 `.env` 中的 `API_PORT=8002`，并检查模型不可用时的演示降级、Embedding 不可用时的检索回退和前端错误状态展示。只有影响启动、连接提示或展示正确性的必要问题才进行修正。

## 6. 不变内容

- 不修改业务服务函数的输入输出契约。
- 不修改 API 路由名称和请求响应结构。
- 不修改 SQLite 表结构。
- 不修改模型 API 调用参数和检索流程。
- 不新增计划任务完成状态等未在本次范围内的功能。

## 7. 验收标准

1. 后端可以在 `127.0.0.1:8002` 启动，`/health` 返回成功。
2. Streamlit 前端可以在 `127.0.0.1:8501` 启动并打开首页。
3. 五个页面可以正常切换，侧边栏状态信息可读。
4. 画像保存、岗位体验反馈、职业分析、行动计划生成、历史计划切换和 Markdown 下载行为保持可用。
5. 模型 API 异常时，页面显示明确状态并保留演示降级能力。
6. 向量检索不可用时，页面显示实际回退状态，不影响基本问答流程。
7. 桌面和窄屏布局中文字、按钮和卡片不发生明显重叠。
8. 改版不引入业务逻辑变更。
