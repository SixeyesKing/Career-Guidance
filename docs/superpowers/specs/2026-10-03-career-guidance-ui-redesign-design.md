# AI 职业规划助手 UI 大改版设计规格

**日期：** 2026-10-03  
**状态：** 已按用户本轮直接改版要求实施并验证  
**范围：** 仅修改 Streamlit 前端表现与页面组织；不改变后端业务逻辑、数据库结构、模型调用和检索流程。

## 1. 目标

参考 `content/` 目录中的现有草稿，将当前 Streamlit 界面改造成浅色、紧凑、专业的职业规划工作台。页面应有完整产品感，内容便于扫描，且真实反映画像、岗位、分析、计划、模型和资料状态。

核心流程保持为：

```text
今日概览 -> 个人画像 -> 岗位探索 -> 职业分析与咨询 -> 行动计划
```

体验任务仍是岗位探索中的可选支线。

## 2. 视觉方向

以 `content/workbench-detail.html` 为首页和全站视觉基准，以以下草稿作为对应页面结构参考：

- `entry-flow-options.html`：首次使用和空画像状态；
- `role-exploration-detail.html`：岗位探索；
- `career-analysis-detail.html`：职业分析与咨询；
- `action-plan-detail.html`：行动计划。

视觉规则：

- 浅灰白背景、白色内容面板、细边框；
- 墨绿色作为主色，用于导航、主按钮和关键操作；
- 橙色作为提醒和待确认状态；
- 统一使用小圆角，控制在 4 至 8px；
- 保持紧凑的信息密度和清晰的标题层级；
- 不使用大面积渐变、粒子背景、自动轮播或持续动画；
- 不使用岗位匹配百分比、录用概率或无法由数据支持的完成度。

## 3. 页面改造

### 3.1 今日概览

首页根据画像和历史数据显示不同状态：

- 空画像：展示首次填写引导，说明画像可以分次补充；
- 部分画像：展示建议下一步和继续补充入口；
- 有历史记录：展示最近分析、咨询、计划和岗位快捷入口；
- 未选择岗位：引导用户比较三个方向。

首页不新增后端接口；优先使用现有 profile、jobs、analyses、plans 等数据。现有接口无法提供的数据不伪造。

### 3.2 个人画像

保留现有字段和保存行为，重组为清晰的基本信息、技能经历、兴趣与准备时间区块。每周时间旁说明只统计职业探索与求职准备，不含课程和作业。保存成功、连接失败和字段状态需要有明确反馈。

### 3.3 岗位探索

三个岗位使用统一卡片并排展示，窄屏改为单列。每张卡片展示岗位简介、日常工作、能力要求和选择操作。画像对照使用“画像中已提到”和“目前还待了解”，不把未填写内容表达为能力缺失。

体验任务保留开始、跳过和反馈保存逻辑，明确展示“可以跳过，不影响继续”。资料状态沿用后端真实返回内容。

### 3.4 职业分析与咨询

保留原有分析生成和对话请求，仅调整展示层级：

1. 当前岗位与画像摘要；
2. 已经提到的基础；
3. 还需要确认，并显示“未知不等于不足”；
4. 建议先做的事及完成标准；
5. 分析参考和资料状态；
6. 继续咨询、常见问题、回答和来源。

模型回退、无资料、接口失败等状态必须按真实状态展示。

### 3.5 行动计划

保留计划生成、历史切换、周预算校验和 Markdown 下载。采用周分组布局展示周目标、任务、预计时间、完成标准和来源状态。周期和每周时间控件如果当前实现已有则优化外观；若后端或当前数据结构不支持新增行为，本次不扩展业务逻辑。

## 4. 导航与状态

侧边栏改为工作台导航，包含：

- 今日概览；
- 个人画像；
- 岗位探索；
- 职业分析；
- 行动计划。

侧边栏保留后端、模型和资料状态，但状态文案必须来自真实接口结果。前端后端地址继续从项目根目录 `.env` 读取，默认端口为 8002；前端页面继续使用 8501。

## 5. 动效边界

只加入轻量、非持续动效：

- 页面内容淡入；
- 卡片悬停轻微上移；
- 按钮 hover、active 和 disabled 状态；
- 进度条平滑过渡；
- 加载状态使用简洁提示。

动效不得改变组件尺寸、导致内容跳动、遮挡文字或影响 Streamlit 控件交互。

## 6. 后端检查

UI 修改完成后检查：

- `GET /health`；
- `GET /status`；
- `GET /profile`；
- `GET /jobs`；
- 页面依赖的分析、计划和聊天接口。

后端检查只做验证和必要的前端连接修正，不重构后端业务逻辑。

## 7. 验收标准

- `ui.py` 语法检查通过；
- 后端 8002 和前端 8501 能按 README 启动；
- 空画像、部分画像和有历史数据状态不报错；
- 五个导航页面可打开；
- 画像保存、岗位选择、体验反馈、分析、咨询、计划生成和 Markdown 下载行为保持可用；
- 模型不可用时准确显示回退或演示状态；
- 向量检索不可用时准确显示关键词检索状态；
- 页面在窄屏下单列展示，无明显横向溢出；
- 不引入静态示例冒充真实用户数据或真实来源。

## 8. 实施记录

首页以墨绿重点区突出下一步，沿用 A1 的白色面板、绿色操作与暖橙提醒。导航使用带图标的原生按钮，替代单选控件。画像表单按三组组织；岗位卡片整合介绍与选择，可选体验独立展示；分析将已知与待确认并列；计划用周次与任务双栏，窄屏转为单列。

公共展示移至 `app/ui_components.py`，CSS 移至 `app/assets/workspace.css`，控件主题由 `.streamlit/config.toml` 管理。使用 Streamlit 1.50 原生容器 key、按钮图标与测试 API，依赖下限同步为 1.50。

同时修正资料 HTML 链接、画像空值预填和岗位切换时的分析/聊天残留；历史计划按岗位筛选，分析历史可回看。后端业务、数据结构与模型调用契约保持原状。验收记录见对应实施计划。
