# AI 职业规划助手 UI 设计规格

**日期：** 2026-10-01  
**状态：** 待用户审阅  
**依据：** [项目设计文档](2026-09-30-ai-career-guidance-design.md) 与本轮 UI 讨论

## 1. 设计目标

界面首先服务于学生日常、分多次完成的职业探索，同时让课程路演可以顺着一条清楚的主流程演示。用户不必一次准备好所有信息；页面要区分已知事实、用户感受、待确认信息和资料依据，不能把缺少信息误写为能力不足，也不输出岗位匹配分数或录用概率。

主要流程为：

```text
今日概览 -> 个人画像 -> 岗位探索 -> 职业分析与咨询 -> 可调整周期的行动计划
```

体验任务是岗位探索中的可选支线。用户参加或跳过，都能继续选择岗位和查看分析。

## 2. 信息架构与导航

采用“日常工作台”作为产品方向。侧边导航包含：

1. 今日概览
2. 个人画像
3. 岗位探索
4. 职业分析
5. 行动计划

新增今日概览作为工作台首页。岗位、画像、分析与计划仍保留独立页面，回访用户可以直接从导航进入任何页面。

桌面端使用侧边导航和主内容区；窄屏下缩窄或折叠导航，内容改为单列。主要页面保持工作型布局，控制标题、间距和装饰的比重，使内容便于扫描。

## 3. 今日概览与首次使用

### 首次使用

首次打开进入今日概览。主区域提供清楚的“开始填写个人画像”操作，并说明画像可以分次补充。画像填写入口说明：

- 年级和专业；
- 接触过的技能，不要求自评熟练程度；
- 课程项目或实习经历；
- 兴趣、意向城市（选填）；
- 每周可投入的职业探索与求职准备时间。

时间字段旁明确说明：此处只统计职业探索与求职准备，不包括上课和课程作业。首次保存后回到工作台，可继续比较岗位。

### 回访用户

今日概览按优先级展示：

1. 建议的下一步及主要操作，例如继续当前岗位分析或打开行动计划；
2. 当前关注岗位，可从此处切换；
3. 每周准备时间及修改画像入口；
4. 最近保存的分析和咨询对话；
5. 后端开发、前端开发、测试开发三个方向的快捷入口。

首页不显示伪造的百分比、完成率或连续使用天数。若没有历史记录，显示开始画像或探索岗位的引导；若没有已选岗位，提供比较三个方向的入口。示例数据和真实用户数据需清楚区分。

## 4. 岗位探索

三个岗位以并排卡片展示，窄屏下改为纵向排列。卡片分别包含：

- 岗位日常工作；
- 常见能力或技术；
- 基于用户画像的初步对照；
- 选择该方向的操作。

对照文字采用“画像中已提到”和“目前还待了解”等措辞。没有填到某项技能时不宣称用户不具备该技能，不显示匹配百分比。

体验任务显示为可选区域，明确写出“可以跳过，不影响继续”。任务反馈保存以下内容：

- 兴趣程度：1 至 5；
- 主观难度：1 至 5；
- 继续意愿：1 至 5；
- 任务状态：跳过、开始但未完成、已完成。

难度的量表说明为：1 很轻松、3 有挑战但能完成、5 非常吃力。界面不把上述指标合并为岗位分数，也不把体验当作能力认证。体验结果可用文字总结，例如“对这类任务有兴趣，觉得难度适中，也愿意继续了解”。三个岗位的反馈可并排回顾，作为用户自我探索的参考。

资料缺失时标注“示例资料，仅用于演示”或“真实资料待补充”；不得编造公司、外部来源链接、发布日期或招聘结论。真实资料接入后展示来源标题、链接和更新时间。

## 5. 职业分析与咨询

职业分析页顶部展示目标岗位、画像摘要、分析更新时间及更新操作。分析正文分为：

1. **已经提到的基础：** 仅引用用户画像明确填写的课程、技术、项目或体验信息；说明熟练程度仍需进一步了解的内容。
2. **还需要确认：** 列出影响判断但用户尚未提供的信息，明确提示“未知不等于不足”。
3. **建议先做的事：** 给出少量可执行行动，每项说明行动内容和观察得到的完成标准。
4. **分析参考：** 展示来源状态、标题、来源名称、链接和更新时间；示例资料醒目标识，无来源时直接说明。
5. **继续咨询：** 保留对话输入、常见问题入口、回答和对应来源。资料不足时明确告知当前没有可靠资料依据。

切换岗位后显示所选岗位的分析和对话，不将另一岗位的内容误显示为当前结果。更新分析生成新的保存记录，原有分析仍可回看。分析底部提供“用这份分析生成行动计划”的主入口。

## 6. 可调整周期的行动计划

页面分别提供两个手动设置：

- **准备周期：** 1 至 12 周，默认 4 周；
- **每周可投入时间：** 默认使用个人画像设置值，计划页可临时调整。此数值指职业探索与求职准备，不含上课和课程作业。

准备周期决定任务分几周安排；每周预算决定单周任务总量。界面可显示周期、周预算和预计总时长。计划实际安排可低于用户预算，不应为了排满时间增加低优先级任务。

生成规则：

- 1 周计划优先保留最关键的项目梳理、岗位准备或交流练习；把未纳入本周的次要事项说明为可延后内容；
- 周期增加时，将较大任务拆分到多个阶段，并安排实践、验证和复盘；
- 每周计划包含周目标、任务、预计时间和可观察的完成标准；
- 每周任务的预计时间合计不得超过该周预算；
- 任务尽量对应分析中已识别的差距或待确认项；
- 用户调整周期或每周时间后，重新生成并保存为新版本，保留旧计划供回看。

计划以周为组显示。每周标题旁显示本周预计用时与周预算，例如“3.5 / 5 小时”，并用低调的时间条辅助比较。页面保留来源状态和 Markdown 下载。准备周期选择使用明确的数值控件，支持快速选 1、2、4、8 周，也支持在 1 至 12 周范围内调整。

本规格确认了周期和周预算的调整方式。逐项编辑任务标题或内容不纳入本版 UI 设计范围，避免与重新生成的规则混淆。

## 7. 状态、文案与错误处理

- **首次且画像为空：** 今日概览显示填写画像的开始入口，不展示空的分析和计划卡片。
- **缺少部分画像：** 允许继续使用；分析把相关项标记为待确认。
- **没有选择岗位：** 提示先探索或选择方向。
- **没有分析：** 行动计划页引导用户先生成分析；可以说明系统可从画像创建通用计划，但不得暗示已完成岗位差距分析。
- **没有检索资料：** 显示无可靠依据状态，不虚构引用。
- **资料是占位内容：** 在卡片、分析、对话引用和计划依据处标注示例状态。
- **模型服务不可用：** 显示可理解的提示并保留已有输入；如果回退到本地演示内容，界面必须准确标明演示模式。
- **计划超出预算或模型结果结构无效：** 不展示为有效的个性化模型计划；提示重新生成或采用清楚标记的受控示例结果。

用户可见文案应使用中文直白表达。模型状态与资料来源状态分开表示，例如“模型生成”不等于“有真实招聘来源”。

## 8. 对当前实现的影响

当前实现已经有四个核心页面、三个岗位、可选体验、职业分析与对话、四周计划、SQLite 保存和 Markdown 导出。本设计增加或明确以下实现工作：

- 增加独立的今日概览页及首次使用状态；
- 明确画像的每周时间口径；
- 将体验状态区分为跳过、已开始、已完成，并展示三个独立反馈量表；
- 将计划周期从固定四周调整为 1 至 12 周，并保持周预算校验；
- 按当前模式和真实来源状态准确展示模型、回退和引用文案；
- 支持查看被重新生成计划替代的旧计划；
- 确保空资料、空画像和异常响应都有清楚的界面状态。

本规格不要求此阶段把招聘 Excel 直接导入知识库，也不要求实时爬取岗位信息。真实资料由用户后续提供后，再依照统一资料格式接入并核验。

## 9. 验收场景

1. 新用户打开项目后看到填写画像的入口；画像可以部分填写并保存，时间字段解释不含课程和作业。
2. 回访用户打开项目后能从今日概览继续最近的岗位分析或计划。
3. 三个岗位可并排比较；未知技能显示为待了解而不是能力缺失；体验任务可跳过。
4. 体验反馈可以分别记录兴趣、难度、继续意愿和任务状态；不计算总分或排名。
5. 职业分析能区分已知基础和待确认信息，建议有完成标准，来源状态可辨认。
6. 用户能生成 1、2、4 或其他 1 至 12 周周期的计划，并调整每周预算。
7. 每周计划时长不超过预算；计划任务显示目标、时间、完成标准；重新生成后旧计划仍可回看。
8. 导出 Markdown 含计划周期、每周预算、任务、完成标准和来源状态。
9. 模型不可用或资料为空时，页面状态与实际内容一致，不把演示内容标成真实分析或真实来源。
