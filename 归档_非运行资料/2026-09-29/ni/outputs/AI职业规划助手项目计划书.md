# AI 职业规划助手项目计划书

## 一 项目概述

### 项目名称

AI 职业规划助手（对话式）

### 项目定位

本项目面向对就业方向不清楚的软件工程专业学生，帮助用户完成“了解岗位方向、发现能力差距、制定下一步计划”的过程。

系统不替用户直接决定职业，而是结合用户画像和公开就业资料，提供有来源依据的岗位介绍、能力分析和准备建议。

### 核心主线

> 从就业迷茫开始，通过对话和知识检索，形成一份可执行的求职准备计划。

## 二 项目目标

在路演前完成一个稳定可运行的系统，完整走通以下流程：

1. 用户填写年级、专业、技能、项目经历和意向岗位。
2. 助手通过对话补充关键信息。
3. 系统介绍岗位特点和基本能力要求。
4. 系统检索知识库，对比用户能力与岗位要求。
5. 系统输出优势、能力差距和改进建议，并显示资料来源。
6. 系统生成四周行动计划，保存对话和规划结果。
7. 用户可以导出 Markdown 格式的规划方案。

## 三 项目范围

### 第一版必须完成

- 支持后端开发、测试开发两个岗位。
- 用户画像填写和修改。
- 对话式职业咨询。
- 就业知识库检索和来源展示。
- 岗位能力差距分析。
- 四周行动计划生成。
- 对话、画像和计划保存。
- Markdown 规划方案导出。
- 一套固定演示数据和演示流程。

### 有余力再完成

- 前端开发等更多岗位。
- 关键词检索与向量检索的混合检索。
- 检索结果重排序。
- 计划任务完成状态和重新规划。
- PDF 导出。
- 简单的召回率和来源命中率统计。

### 暂不作为第一版要求

- 全网实时招聘信息爬取。
- 自动投递简历。
- 完整的用户注册和权限系统。
- 自动判断真实薪资。
- 复杂心理测评。

## 四 产品模块

### 1 用户画像模块

收集以下信息：

- 年级和专业方向
- 已学技术和课程
- 项目或实习经历
- 感兴趣的岗位
- 意向城市
- 每周可投入时间

画像信息存入 SQLite，并允许用户后续修改。

### 2 岗位探索模块

第一版支持后端开发和测试开发。每个岗位展示：

- 主要工作内容
- 常见技能要求
- 常见工具和技术
- 适合的准备方向
- 知识资料来源

### 3 对话咨询模块

支持自然语言多轮对话，重点回答：

- 我适合哪个岗位方向？
- 这个岗位需要学习什么？
- 我现在还缺哪些能力？
- 校招和面试应该如何准备？

系统在资料不足时应明确说明，而不是编造确定结论。

### 4 RAG 知识库模块

知识库先整理 30 至 60 份公开资料，内容包括：

- 岗位能力要求
- 校招流程
- 秋招、春招和实习时间节点
- 技术学习路径
- 面试准备资料

每份资料至少保存标题、岗位类别、正文、来源名称、来源链接和更新时间。

### 5 能力差距分析模块

输出固定为四部分：

- 已有优势
- 岗位要求
- 当前差距
- 建议行动

每项差距和建议尽量对应知识库中的资料来源，这部分作为项目主要技术亮点。

### 6 行动计划模块

根据用户画像和目标岗位生成四周计划。每周包含：

- 本周目标
- 具体任务
- 预计投入时间
- 完成标准

计划要具体到可以执行，例如“完成一个带登录功能的 Spring Boot 项目，并补充接口说明”，而不是只写“加强编程能力”。

### 7 保存与导出模块

保存：

- 用户画像
- 会话和消息
- 能力分析结果
- 行动计划

第一版导出 Markdown，PDF 作为增强功能。

## 五 技术方案

| 层次 | 技术 | 用途 |
|---|---|---|
| 前端 | Streamlit | 画像表单、对话页面、规划展示和导出 |
| 后端 | FastAPI | 提供画像、对话、检索和规划接口 |
| 对话编排 | LangChain | 提示词、上下文和 RAG 流程编排 |
| 向量检索 | Chroma | 保存知识库向量并进行语义检索 |
| 关系数据 | SQLite | 保存画像、会话和计划 |
| 模型服务 | GLM 或 OpenAI 兼容接口 | 对话、分析和计划生成 |
| 版本管理 | Git | 代码协作和版本记录 |

建议使用 `.env` 保存 API 密钥，不要把密钥提交到 Git 仓库。

## 六 四周倒排计划

### 第 1 周：确定范围并跑通最小闭环

目标：完成“填写画像 → 提问 → 返回回答 → 生成简单计划”。

- 确定后端开发和测试开发两个岗位。
- 确定画像字段、接口格式和计划输出格式。
- 准备第一批知识库资料。
- 搭建 FastAPI、Streamlit 和 SQLite 基础结构。
- 完成一个可以从头操作到尾的版本。

### 第 2 周：完成 RAG 问答和来源展示

目标：回答有依据，能够展示资料出处。

- 清洗和整理知识文档。
- 完成文档切分、Embedding 和 Chroma 入库。
- 实现基础向量检索。
- 在回答中显示来源名称和链接。
- 增加资料不足时的提示。
- 准备 10 个固定测试问题。

### 第 3 周：完成差距分析、行动计划和保存

目标：完成项目的主要产品价值。

- 实现岗位要求与用户画像对比。
- 输出优势、差距和建议行动。
- 生成四周行动计划。
- 保存画像、对话和计划。
- 实现 Markdown 导出。
- 有余力时加入混合检索或任务状态。

### 第 4 周：联调、测试和路演准备

目标：保证现场演示稳定、流程清晰。

- 完成前后端联调。
- 固定一套演示用户画像和五个演示问题。
- 测试来源展示、计划生成、保存和导出。
- 测试网络异常或 API 不可用时的备用方案。
- 完成路演 PPT、演示脚本和项目分工说明。
- 准备关键页面截图和本地演示数据。

## 八 路演演示脚本

以一名大三软件工程学生为例：

1. 填写“学过 Java，做过课程项目，没有实习，不确定后端还是测试开发”。
2. 助手通过追问补充技能和兴趣信息。
3. 展示后端开发和测试开发的岗位差异。
4. 用户选择后端开发。
5. 系统检索岗位要求，展示资料来源。
6. 系统指出用户已有 Java 基础，但缺少数据库优化和完整项目经历。
7. 系统生成四周准备计划。
8. 保存并导出 Markdown 规划方案。

## 九 验收标准

- 能在本地启动前端和后端。
- 能完成一套固定演示流程。
- 用户画像可以保存和读取。
- 对话能够返回模型回答。
- RAG 回答至少能显示相关来源。
- 岗位分析包含优势、差距和行动建议。
- 行动计划包含四周目标、任务和完成标准。
- 规划结果可以导出 Markdown。
- 对无资料问题有明确提示，不编造确定信息。
- 路演时有备用截图或本地演示数据。

## 十 项目风险与应对

| 风险 | 应对措施 |
|---|---|
| API 调用失败或网络不稳定 | 准备固定演示数据、截图和本地示例答案 |
| 知识库资料太少 | 先保证两个岗位和四类核心资料，逐步扩充 |
| 回答出现幻觉 | 强制提供检索上下文，要求显示来源，资料不足时提示 |
| 前后端联调拖延 | 第 1 周确定接口格式，每周合并一次可运行版本 |
| 功能过多导致延期 | 优先完成第一版必须功能，增强功能按剩余时间安排 |
| 组员任务互相等待 | 每项任务指定负责人和交付物，使用 Git 分支或任务看板跟踪 |
