# 画像、岗位探索与职业分析交互优化设计

## 目标

优化个人画像、岗位探索和职业分析的四处交互问题，降低表单填写、方向比较和分析问答中的认知成本，并确保更新后的职业分析结果优先可见。

## 已确认范围

1. “接触过的技术”多选框在获得焦点、悬停或点击时能稳定展示候选项。
2. “你更愿意做哪些事情？”保留内置事项，同时允许用户输入自定义事项；自定义事项与内置事项合并去重，并沿用现有 `profile.interests` 字段保存。
3. 岗位探索页面先展示“比较三个方向”，再展示“动手试试”体验区。
4. 职业分析页面先展示当前最新分析，再展示职业问答和历史记录；点击“更新职业分析”成功后，当前问答展示被清空，最新分析立即置顶显示。

## 方案

### 表单交互

沿用 Streamlit 原生 `multiselect`，通过稳定的 widget 配置和局部 CSS 提升焦点、悬停、点击后的下拉可见性，不引入新的前端组件。技术候选项仍由页面内置列表提供，用户补充技术继续使用现有“其他技术”输入框。

兴趣事项采用“内置多选 + 自定义事项输入框”。保存时将内置选中值与自定义文本按中英文逗号拆分、清理空白、去重后写入 `interests`；读取时将已保存的自定义值加入多选候选项，避免保存后消失。空值不产生空标签。

### 页面层级

岗位探索保持现有体验任务逻辑，只调整渲染顺序：方向比较区先渲染，体验任务面板及反馈表单放在其后。

职业分析保留当前岗位选择器和更新按钮。更新成功后设置最新分析、分析岗位，并清空 `chat_display`、`conversation_id`、`loaded_conversation_id`，避免旧问答继续占据首屏。渲染顺序改为：分析摘要与结果、建议行动和资料依据、职业问答、历史分析版本。

## 数据流与兼容性

- 不新增数据库表、不修改 API schema。
- `ProfileInput.interests` 继续为字符串列表，现有旧数据可直接读取。
- 自定义兴趣只在保存个人画像时写入；刷新页面后从 `/profile` 恢复。
- 分析刷新只影响当前页面会话中的问答展示，不删除后端已保存的历史对话；历史对话仍可通过“打开历史对话”加载。
- 切换岗位时沿用现有 `choose_job` 清理分析和问答会话状态。

## 错误与边界处理

- 自定义兴趣输入为空或只包含分隔符时忽略。
- 与内置选项重复的自定义兴趣只保存一份，保留第一次出现的顺序。
- 更新分析请求失败时不清空已有分析或问答，继续显示当前内容并由现有 API 错误提示反馈。
- 只有更新分析请求成功返回结果后才清空问答状态。

## 验证

- UI 回归测试覆盖：技术选项候选可见、自定义兴趣保存与恢复、方向比较位于体验任务之前、更新分析后分析结果位于问答之前且旧问答被清理。
- 运行现有 `scripts/test_ui.py` 全量测试，确保画像、岗位切换、问答、计划和离线场景不回归。
- 使用 Streamlit AppTest 检查自定义兴趣合并、去重和刷新后的页面状态；用本地浏览器确认桌面与窄屏下下拉框及页面层级无重叠。
